# Gym Management System - Backend

This backend provides the API services for the GymPro management system. It's built with Node.js, Express, and MongoDB.

## Features

- User Authentication (JWT-based: registration, login)
- Role-based Access Control (Admin, Trainer, Member)
- User Profile Management (view own, update own basic details)
- Admin Management:
    - User Listing & Editing (role, status, plan assignment)
    - Membership Plan CRUD
    - Facility CRUD
- Trainer Profile Management (specializations, bio, availability)

## Prerequisites

- Node.js (v14.x or later recommended)
- MongoDB (local instance or Atlas connection string)
- npm (Node Package Manager)

## Setup and Installation

1.  **Clone the repository (or ensure you are in the `gym-management-app` root directory if generated by an agent).**

2.  **Navigate to the backend directory:**
    ```bash
    cd backend
    # Or from root: cd gym-management-app/gym-management-app/backend
    ```

3.  **Install dependencies:**
    ```bash
    npm install
    ```

4.  **Environment Variables:**
    Create a `.env` file in the `backend` directory. Copy the contents of `.env.example` (if provided) or use the following template:
    ```env
    PORT=5001
    MONGO_URI=mongodb://localhost:27017/gym_management_db_dev
    # Replace with your MongoDB connection string if different (e.g., for MongoDB Atlas)

    JWT_SECRET=yourStrongJwtSecretKeyHere # Replace with a strong, unique secret
    JWT_EXPIRE=1h # Or use milliseconds e.g., 3600000

    # NODE_ENV=development # Optional: set to 'production' for production builds
    ```
    **Important:** Ensure `MONGO_URI` points to your MongoDB instance and `JWT_SECRET` is a secure, unique string.

## Running the Server

-   **Development mode (with Nodemon for auto-restarts):**
    ```bash
    npm run server
    ```
    The server will typically start on `http://localhost:5001` (or the `PORT` specified in `.env`).

-   **Production mode:**
    ```bash
    npm start
    ```

## Running Tests

-   Jest is used for testing.
    ```bash
    npm test
    ```
    This will run unit and integration tests. Ensure your test database (if configured separately for tests) is accessible.

## API Endpoint Summary

A brief overview of available API endpoints. All are prefixed with `/api`.

### Authentication (`/auth`)
-   `POST /register`: Register a new user.
    -   Body: `{ username, email, password, role? }`
-   `POST /login`: Login an existing user.
    -   Body: `{ email, password }`
-   `GET /me`: Get current logged-in user's details. (Protected)
-   `PUT /updatedetails`: Update current logged-in user's basic details (firstName, lastName). (Protected)
-   `GET /admin-test`: Test endpoint for admin role. (Admin Protected)

### Users (`/users`) - Admin Only
-   `GET /`: Get all users (members and trainers).
-   `GET /:id`: Get a single user by ID.
-   `PUT /:id`: Update user details (role, isActive, plan, etc.).

### Plans (`/plans`)
-   `POST /`: Create a new membership plan. (Admin Protected)
-   `GET /`: Get all active membership plans. (Public)
-   `GET /all`: Get all plans, including inactive. (Admin Protected)
-   `GET /:id`: Get a single plan by ID. (Public)
-   `PUT /:id`: Update a plan. (Admin Protected)
-   `DELETE /:id`: Delete a plan. (Admin Protected)

### Facilities (`/facilities`)
-   `POST /`: Create a new facility. (Admin Protected)
-   `GET /`: Get all active facilities. (Public)
-   `GET /all`: Get all facilities, including inactive. (Admin Protected)
-   `GET /:id`: Get a single facility by ID. (Public)
-   `PUT /:id`: Update a facility. (Admin Protected)
-   `DELETE /:id`: Delete a facility. (Admin Protected)

### Trainer Profiles (`/trainer-profiles`) - Trainer Only (for `/me`)
-   `GET /me`: Get the current trainer's profile. (Trainer Protected)
-   `POST /me`: Create or update the current trainer's profile (specializations, bio, availability). (Trainer Protected)

*(Protected routes require a JWT in the `Authorization: Bearer <token>` header).*

## Project Structure (Key Directories)

-   `models/`: Mongoose schemas for database models (User, Plan, Facility, TrainerProfile).
-   `routes/`: API route definitions.
-   `middleware/`: Custom middleware (e.g., authentication, authorization).
-   `__tests__/`: Jest test files.
-   `server.js`: Main Express server setup.
-   `.env`: Environment variables (ignored by Git).
-   `package.json`: Project dependencies and scripts.
